Обсуждение — отдельный слой над вашими файлами. Вы и агенты отвечаете на конкретную мысль, а не пытаетесь вспомнить, о какой версии шла речь.

Задача: открыть локальный файл из Finder или CLI, обсуждать фрагменты с агентами, сохранять историю и восстанавливать её по событиям.
Файл — ваш.Остаётся в Obsidian, редакторе или папке.
Контекст точный.Комментарий закреплён за неизменяемым снимком.
Агент — участник.Упоминания, ответы и видимая доставка.
История полная.События восстанавливают решения, ветки и реакции.
01 / Посмотреть в действии

Один разговор. Два времени.

Выбор версии показывает старый текст с текущим обсуждением. Шкала истории восстанавливает и текст, и обсуждение на прошлый момент. Это разные действия.

02 / Устройство решения
Одно ядро. Все точки входа.
Небольшой локальный сервис владеет историей. Браузер, CLI и агенты работают через одинаковые команды. Событие сначала сохраняется, затем доставляется подписчикам.
── Команда / сохранение┄┄ Доставка после commitЛокальный modular monolith
История принадлежит приложению.
Документы и сессии агентов могут меняться. Снимок + anchor + журнал продолжают объяснять, кто, что и в каком контексте сказал. Replay не запускает инструменты повторно.
Сабагент должен подтвердиться.
«Родитель получил запрос», «native child вызван» и «child ответил» — разные receipts. Parent fallback нельзя показывать как ответ выбранного специалиста.


03 / Что храним
Не номер строки. Сохранённый смысл.
Снимок + точный диапазон
UUID документа не зависит от пути. Hash определяет содержимое снимка. Anchor хранит диапазон, цитату и соседний текст. Переименование и новая редакция не стирают исходную связь.
S1 → comment → reply → reaction
Один журнал, два расположения
Central — одна локальная база для разных папок. Sidecar — .discuss/store.sqlite на папку. Для Git/iCloud — central + переносимый архив. Копирование одного файла само не переносит sidecar.
comment.created
  storeId + seq       → точный порядок внутри хранилища
  snapshotId          → неизменяемый текст
  parentCommentId     → адресат ответа
  commandId           → повтор команды без дубликата
  correlationId       → связь с запросом агенту

as-of #42 = reduce(events ≤ 42)
// без запросов к LLM и без перезаписи исходного файла

Свой небольшой core
Базовая рекомендация		Контроль snapshots, событий и локальной SQLite. Независимость от harness.Больше собственного UI и доменной логики; использовать существующие компоненты точечно.
Критерий выбора: Agent-Native остаётся реальным кандидатом. Либо его kit-таблицы — восстановимые проекции одного event core в одной БД, либо сохраняем независимый SQLite core. Две базы-истины не вводим.
Оба референса уже имеют часть нужной механики. Решение о собственной основе — проектный вывод, не утверждение об отсутствии у них комментариев или истории. Agent-Native kit · Plannotator API.


05 / Реализация
От разговора — к надёжному инструменту.
01
Проверить UX на стабах
Выделение, reply, ветка, реакция, resolve; новая версия и старый контекст; очередь и история. Это текущий прототип.
02
Закрыть четыре вопроса совместимости
Native child round trip в Codex; native child receipt в Claude; атомарная запись custom events и kits в Agent-Native; воспроизводимый replay. Зафиксировать выбор движка.
03
Сделать вертикальный срез истории
Реальный файл → снимок → комментарий → событие → рестарт → тот же контекст. Central, затем sidecar. Export/import восстанавливает состояние.
04
Достроить разговор и anchors
Replies и независимые ветки, reactions, resolve/reopen, точное as-of. Проверить одинаковые цитаты, emoji, удалённый фрагмент и сохранение файла во время комментария.
05
Подключить живых агентов
Managed sessions, parent bridge, outbox, дедупликация и видимая неопределённая доставка. Reply к агенту продолжает разговор без повторного @.
06
Войти в повседневный процесс
CLI и Finder Quick Action, подписки с курсором, восстановление после разрыва, пилот на реальных заметках. Затем решать о native wrapper и совместном сервере.


06 / Компромиссы
Что делаем явно.
Обсуждаем, не редактируем.
Co-editing и CRDT не нужны для первого сценария. Исходный Markdown даёт точные диапазоны; красивый rendered view потребует карты позиций.
At-least-once, с receipts.
События можно повторить. Внешний вызов LLM не обещает exactly-once. Неопределённая доставка видна и сверяется с сессией.
Старое не притворяется новым.
Изменённый/неоднозначный фрагмент остаётся в старом снимке. Автопривязка — кандидат; подтверждение человека — событие.
Демо не выдаёт себя за продукт.
localStorage и таймеры имитируют store и агентов. Finder/CLI — сценарии. Реальные adapters, SQLite crash safety и native install — gates будущей реализации.
